# FND-003 — Vercel web, Northflank API/worker, Supabase DB/Auth ve kontrollü release hazırlığı kur

**Epic:** Foundation  
**Öncelik:** P0  
**Boyut:** M (XS/S/M/L; takvim tahmini değildir)  
**Bağımlılıklar:** FND-001, FND-002  
**Durum:** REVIEW

## Sonuç / Ticket amacı
Vercel web, iki ayrı Northflank servisi üzerinde API/worker, explicit migration job ve Supabase DB/Auth bağlantısı için deployment-ready yapılandırma ile operasyon sözleşmesini kur; gerçek harici deployment ve smoke'u Executor doğrulamasına bırak.

## Kabul kriterleri
- [ ] Java 25 uyumlu aynı immutable image, `APP_MODE=api`, `APP_MODE=worker` ve tek seferlik `APP_MODE=migrate` davranışlarını sağlar; API/Worker startup migration çalıştırmaz.
- [ ] Northflank'te API ve Worker iki ayrı sürekli servis, migration ise rollout öncesi başarıyla bitmesi gereken job olarak tanımlanır; aynı image/revision kullanılır.
- [ ] API health/readiness DB erişimini, Worker process canlılığı ve redacted heartbeat'i doğrular; eksik production DB/Auth environment sözleşmesi fail-fast olur. Tam JWT authentication/authorization IAM-001 kapsamındadır.
- [ ] Supabase PostgreSQL 17 hedefi ve mevcut PostgreSQL 18.3 test semantiği korunur; production DB bağlantısı TLS kullanır ve küçük connection pool ile çalışır.
- [ ] Vercel monorepo kökü `frontend/`, Production Branch `main` ve Preview/Production environment ayrımı belgelenir; Preview hiçbir koşulda production API/DB'ye sessiz fallback yapmaz.
- [ ] Prod secretlar repository, PR workflow'u, preview veya loglarda çıkmaz; frontend'e yalnız tarayıcıya açık `NEXT_PUBLIC_*` değerleri verilir.
- [ ] Başarılı main CI sonrası protected `release-ready` job Northflank workflow'unu completion'a kadar izler ve API readiness + exact release SHA smoke yapar; Vercel production domain assignment bu check'i bekler. Deployment Checks yoksa staged `--skip-domain` → smoke → promote alternatifi kullanılır; harici entegrasyon kurulmadan akış `VERIFIED` sayılmaz.
- [ ] Çalışan URL, deploy logu, schema version, smoke ve commit SHA kanıtı yalnız gerçek deployment sonrasında handoff'a eklenir; olmayan URL/deployment uydurulmaz.

## Zorunlu doğrulama
- Docker build; API/Worker/Migration mode testleri; PostgreSQL 17 + 18.3 migration uyumluluğu; TLS/env/secret kontrolü; deploy logs, URL, schema version ve live smoke yalnız harici kurulum tamamlanırsa

## Kapsam dışı
İşlem veya kural business logic yok.

## Risk / preflight kontrolü
Hosting hesabı, secret, provider entegrasyonu, plan/kota ve faturalandırma harici erişim gerektirir. Kod ve yapılandırma incelemeye alınabilir; fakat gerçek rollout/smoke tamamlanmadan ticket `DONE` olamaz. Base commit FND-002 CI değişikliklerini içerir, ancak `backlog/FND-002.md` statüsü hâlâ `PLANNED` olduğundan bu metadata çelişkisi Executor tarafından ayrıca çözülmelidir.
