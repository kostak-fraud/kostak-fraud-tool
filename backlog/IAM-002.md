# IAM-002 — Frontend Supabase Auth ve authenticated API client

**Epic:** Security
**Öncelik:** P0
**Boyut:** M
**Bağımlılıklar:** IAM-001, UI-001
**Durum:** REVIEW

## Sonuç / Ticket amacı

Next.js frontend'e Supabase Auth oturum akışını entegre et ve sonraki UI ticket'larının kullanacağı, mevcut access token'ı güvenli biçimde taşıyan ortak API istemcisini oluştur.

İlk sürüm yalnız e-posta/parola girişini kapsar. Public sign-up, davet, parola sıfırlama, tenant provisioning ve kullanıcı yönetimi UI'si kapsam dışıdır.

## Kabul kriterleri

### Supabase Auth entegrasyonu

- [x] Kurulu Next.js sürümü ve güncel Supabase SSR yaklaşımıyla uyumlu browser/server client ve cookie session yenilemesi bulunur.
- [x] `@supabase/ssr` ve `@supabase/supabase-js` sabitlenmiş sürümlerle eklenir; pnpm lockfile güncellenir.
- [x] Yalnız `NEXT_PUBLIC_SUPABASE_URL` ve `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` kullanılır; service role/secret frontend'e eklenmez.
- [x] E-posta/parola login `signInWithPassword` ile çalışır; mevcut session yenilemede geri yüklenir.
- [x] Logout Supabase session'ını sonlandırır ve login ekranına yönlendirir.
- [x] Server-side kontrol cookie session verisine kör güvenmez; doğrulanmış claim kullanır.

### Route koruması ve durumlar

- [x] `/login` kimliği doğrulanmamış kullanıcıya açıktır; `/transactions` ve `/rules` doğrulanmış session ister.
- [x] Next.js 16 `proxy.ts` server-side guard ile server page doğrulaması birlikte kullanılır; doğrulama bitmeden korumalı içerik gösterilmez.
- [x] Yerel return-to desteklenir; harici origin, protocol-relative ve backslash tabanlı yönlendirmeler reddedilir.
- [x] Loading, login error, expired session, configuration, backend membership/permission ve logout durumları anlaşılır biçimde ayrılır.
- [x] Session yüklenirken sahte kullanıcı veya tenant bilgisi gösterilmez.

### Ortak authenticated API client

- [x] Base URL yalnız `NEXT_PUBLIC_API_BASE_URL` üzerinden gelir; eksik/geçersiz değerde sessiz fallback yoktur.
- [x] Her authenticated istekte mevcut Supabase access token'ı `Authorization: Bearer` header'ına yazılır; query veya loglara yazılmaz.
- [x] JSON, boş/JSON olmayan response, network hatası ve beklenmeyen HTTP durumları öngörülebilir typed hatalara dönüşür.
- [x] `401` en fazla bir refresh/retry yapar; tekrar eden `401` session'ı sonlandırır ve sonsuz retry yapmaz.
- [x] `403` otomatik logout yapmaz; membership/permission sorunu olarak ayrı ele alınır.
- [x] İstemci Supabase PostgreSQL tablolarına doğrudan erişmez.

### Identity ve UI

- [x] Login sonrası `GET /api/v1/identity/me` çağrılır ve response typed `IdentityContext` olarak doğrulanır.
- [x] Tenant, rol ve permission bilgisi yalnız backend response'undan gelir; UI permission bilgisi sadece sunum/navigasyon içindir.
- [x] Backend `403` veya membership eksikliği login başarısızlığı gibi gösterilmez.
- [x] Login ekranı mevcut tasarım token'larıyla uyumlu, erişilebilir label/klavye/loading/error durumlarına sahiptir ve tekrar gönderimi engeller.
- [x] Authenticated workspace görünür logout kontrolü sunar; mevcut AppShell/navigasyon gereksiz yeniden tasarlanmaz.

## Zorunlu doğrulama

- Login form render ve erişilebilir alanlar.
- Başarılı login yönlendirmesi ve hatalı giriş mesajı.
- Mevcut session'ın sayfa yenilemesinde geri yüklenmesi ve logout yönlendirmesi.
- Session'sız protected route reddi.
- Bearer header, tek `401` refresh/retry ve `403` session koruması.
- Eksik environment değerinin import-time crash olmadan açıklanması.
- Token/parola/secret değerlerinin loglanmaması.
- Güvensiz harici return-to değerlerinin reddi.
- `pnpm install --frozen-lockfile`, lint, typecheck, test ve build.

## Kapsam dışı

Public sign-up, parola sıfırlama, kullanıcı daveti/yönetimi, tenant provisioning/seçimi, backend refactor, DB migration/RLS değişikliği, staging veri üretimi ve production deployment yoktur.

## Risk / doğrulama notu

Vercel Preview'da `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` eksik olduğundan ve staging'de Auth kullanıcısı/tenant/membership/transaction bulunmadığından gerçek staging login → identity başarı akışı bu ticket'ta doğrulanamaz. İzole mock testleri credential gerektirmez; canlı akış `UNVERIFIED` olarak handoff'a yazılır.
