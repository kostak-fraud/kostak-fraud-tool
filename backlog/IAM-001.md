# IAM-001 — Tenant, kullanıcı üyeliği, izin modeli ve Supabase Auth JWT doğrulamasını backend'e entegre et

**Epic:** Security  
**Öncelik:** P0  
**Boyut:** M  
**Bağımlılıklar:** FND-001  
**Durum:** REVIEW

## Sonuç / Ticket amacı
Supabase JWT signature/issuer/audience/expiry doğrulaması, server-side tenant membership çözümü ve permission-based endpoint authorization için backend güvenlik temelini kur.

## Kabul kriterleri
- [x] JWT signature, issuer, audience ve expiry kontrolleri Spring Security Resource Server ile doğrulanır; testlerde geçersiz token reddedilir.
- [x] User-to-tenant membership server-side resolve edilir; client-provided tenant ID yetki kaynağı değildir.
- [x] Viewer/Analyst/Rule Author/Tenant Admin permission matrix'i database-backed role_permissions ile tanımlanır.
- [x] Tenant Admin membership endpoint'i users.manage permission ister; Viewer 403 alır.
- [x] Tenant A Admin, Tenant B membership ID'sini okuyamaz; integration test 404 ile tenant existence sızıntısını önler.
- [ ] Sonraki transaction/rule/investigation endpoint'leri aynı permission guard ve tenant-scoped repository sözleşmesini kullanır.

## Zorunlu doğrulama
- Testcontainers cross-tenant + 403 integration tests.
- JWT signature, issuer, audience ve expiry unit/integration tests.
- Backend Maven verify ve PR CI.

## Kapsam dışı
Tam kullanıcı daveti/abonelik/SaaS onboarding ve user-management UI yok. Transaction/rule business logic ayrı ticket'larda.

## Risk / preflight kontrolü
Supabase Auth asymmetric signing key ve issuer/audience environment değerleri gereklidir. Deployed API bu değerler eksikken fail-fast olmalıdır. İlk MVP tek aktif tenant membership kabul eder; bir kullanıcının birden çok aktif membership'i varsa otomatik tenant seçimi yapılmaz.
